# Architecture decision records

> [Back to BizSaathi overview](../../README.md)

This folder records durable architectural decisions, including context, chosen approach, and consequences. The numbered ADRs explain decisions such as modular-monolith shape, approval boundaries, LangGraph runtime, and grounded customer intent planning.

## Use

Write an ADR when changing an established architectural decision or adding a dependency, model, or service. Keep status and trade-offs explicit; link implementation tasks and affected architecture documentation.

## Metrics and impact

ADRs are decision records, not runtime telemetry. No quantitative impact is claimed here. Their value is preserving why the system is shaped as it is and making future changes reviewable.
