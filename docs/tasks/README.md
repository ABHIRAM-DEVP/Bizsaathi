# Implementation tasks

> [Back to BizSaathi overview](../../README.md)

Task files define bounded work, dependencies, and acceptance criteria. The implementation workflow starts from one task and maps each acceptance criterion to a test or command result.

## Use

Read a task's dependencies and named docs before implementation. Keep task scope explicit, avoid treating assumptions as facts, and record blockers rather than weakening tests. Task files are plans/acceptance contracts, not evidence that work has shipped.

## Metrics and impact

Task completion is not a product metric. Verification evidence belongs in actual test/command output or a clearly scoped status report.
